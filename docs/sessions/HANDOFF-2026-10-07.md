## Key Learnings (Most Important for Next Session)

### 1. Dictionary baseline has fundamental limitations

**Expected:** Dictionary matching would achieve modest but reasonable performance (F1 ~0.4-0.6).

**Actual:** F1 = 0.097 — much worse than expected.

**Why:**
- **Vocabulary coverage** — Dictionary only contains entities from training set. New entities in test set (e.g., "Famotidine") are false negatives.
- **Context blindness** — Dictionary matches entities everywhere they appear, but BC5CDR only annotates entities relevant to the paper's main findings. "Histamine" appears in many abstracts but is only annotated when it's a focus of the study.
- **No generalization** — Can't recognize variations or related terms not in dictionary.

**Lesson:** Dictionary approach is useful as a transparent baseline, but transformer NER is essential for contextual understanding and generalization to unseen entities.

---

### 2. Short entity filtering is critical

**Expected:** min_length=3 would filter most false positives.

**Actual:** Many false positives from 3-character common words ("ist", "str", "all", "and", "the", "was").

**Fix:** Increased min_length to 4 and added explicit COMMON_WORDS filter.

**Result:** Precision improved from 0.065 to 0.116 (+79%), false positives reduced from 11,919 to 6,219 (-48%).

**Lesson:** Always inspect false positives and filter common words explicitly, not just by length.

---

### 3. Span boundary handling is tricky

**Issue:** Initial implementation matched spans with leading/trailing whitespace (e.g., " clonidine", "hypertensive ").

**Fix:** Strip whitespace from matched spans and adjust offset/length accordingly.

**Lesson:** Always verify span boundaries by extracting text at predicted offset and comparing to predicted text.

---

### 4. BC5CDR annotation is selective, not exhaustive

**Discovery:** Many "false positives" are actually real biomedical entities (e.g., "histamine", "sodium", "indomethacin") that appear in the text but are not annotated in gold standard.

**Why:** BC5CDR annotators only mark entities relevant to the paper's main findings, not every chemical/disease mentioned.

**Implication:** This inflates false positive count — some "FPs" are correct extractions that just aren't in gold standard. True performance may be slightly better than measured.

**Lesson:** When evaluating on BC5CDR, remember that gold standard is not exhaustive. Consider manual inspection of "false positives" to understand true error rate.

---

### 5. Case normalization works, but vocabulary gap remains

**Discovery:** "Famotidine" normalizes to "famotidine" correctly, but "famotidine" is not in dictionary because it wasn't in training data.

**Implication:** Case normalization is necessary but not sufficient — need contextual generalization (transformer) to handle unseen entities.

**Lesson:** Transformer NER should be evaluated not just on overall F1, but specifically on entities not in dictionary baseline (measure generalization gain).

## Known Issues

### Implementation issues

1. **Dictionary file size** — `bc5cdr_dictionary.json` is 2.5 MB (2,328 entries). Not a problem now, but could grow with larger corpora.
2. **No word boundary checking** — Dictionary matches "histamine" inside "antihistamine" (though this is filtered by overlap removal).
3. **Slow evaluation** — Sliding window over all possible spans is O(n²) — acceptable for 500 abstracts, but would be slow for larger corpora.

### Data issues

1. **BC5CDR format** — BioC XML is verbose; parsing is correct but could be simplified with `bioc` library.
2. **MESH IDs** — Some entities have `MESH: -1` (unmapped terms like "nalozone" — likely typo for "naloxone").
3. **Entity type ambiguity** — Some entities could be both Chemical and Disease depending on context (e.g., "toxicity" vs "toxic").

## Decision Log

### 2026-10-07: Dictionary baseline approach

**Context:** Need transparent baseline for NER before transformer fine-tuning.

**Decision:** Implement dictionary matching with:
- min_length=4 (filter short entities)
- COMMON_WORDS filter (remove "ist", "str", "all", etc.)
- Overlap removal (keep longest match)
- Exact span matching for evaluation

**Alternatives considered:**
- scispaCy with biomedical models — Rejected: wanted transparent baseline first
- Only transformer — Rejected: need baseline for controlled comparison

**Consequences:**
- Baseline F1 = 0.097 (much lower than expected)
- Revealed fundamental limitations: vocabulary coverage, context blindness
- Transformer NER now clearly motivated (not just "because it's SOTA")
