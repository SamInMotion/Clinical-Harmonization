## EXP-001: Training-derived abbreviation expansion

**Date:** 2026-10-11  
**Status:** COMPLETED — REJECTED  
**Research question:** Can acronym aliases learned from BC5CDR training
abstracts improve dictionary-NER recall without unacceptable precision loss?

**Hypothesis:** Mapping acronym-like gold mentions to long-form expansions
found in the same training abstract would recover abbreviation false
negatives and improve F1.

**Method:**

- Built abbreviation aliases exclusively from the BC5CDR training set.
- Used parenthetical patterns of the form `long form (ACRONYM)`.
- Added an alias only when its expansion matched an existing training
  dictionary entry with the same entity type.
- Compared the baseline and expanded dictionaries on the BC5CDR
  development set.
- Used Gate C-2 location-level, type-aware exact-span matching.

**Development result:**

| Metric | Baseline | Abbreviation-expanded | Difference |
|---|---:|---:|---:|
| Precision | 0.8158 | 0.7390 | -0.0768 |
| Recall | 0.5847 | 0.5935 | +0.0088 |
| F1 | 0.6812 | 0.6583 | -0.0229 |
| True positives | 5,728 | 5,814 | +86 |
| False positives | 1,293 | 2,053 | +760 |
| False negatives | 4,069 | 3,983 | -86 |

**Decision:** Reject the abbreviation-expanded dictionary as the active
baseline.

**Why it did not work:**

- It recovered only 86 additional true positives.
- It introduced 760 additional false positives.
- The net effect was a 0.0229 F1 decrease.
- The acronym-to-expansion mapping was too permissive: an acronym could be
  linked to a plausible but incorrect or overly broad long form.
- The precision loss outweighed the small recall gain.

**Provenance:**

- Expansion dictionary: `data/terminology/bc5cdr_dictionary_abbreviation_expanded.json`
- Alias provenance: `data/terminology/bc5cdr_abbreviation_aliases.json`
- Comparison result: `output/evaluation/development_abbreviation_expansion_comparison.json`
- Comparison report: `output/evaluation/development_abbreviation_expansion_comparison.md`
- Implementation: `src/ner/abbreviation_expansion.py`
- Development comparison: `src/ner/evaluate_development_comparison.py`

**Follow-up:** Do not use this expansion for test-set evaluation. Investigate
partial-overlap false negatives before attempting another lexical expansion.

## EXP-003: Tokenizer-offset BIO labeling

**Date:** 2026-10-11  
**Status:** COMPLETED — ADOPTED  
**Research question:** Can tokenizer-provided character offsets produce
correct BIO labels for multi-location BC5CDR annotations?

**Hypothesis:** Replacing the `str.find()` token-offset reconstruction with
Hugging Face tokenizer offset mappings will make BIO labeling reliable for
multi-location annotations.

**Method:**

- Used PubMedBERT’s fast tokenizer with `return_offsets_mapping=True`.
- Passed tokenizer character offsets into `_build_bio_labels()`.
- Removed the prior `str.find()` reconstruction.
- Retained the Gate C-3 policy: first location receives `B`, subsequent
  locations of the same annotation receive `I`.
- Audited 20 development-set passages containing multi-location annotations.

**Result:**

- Focused tests: 8 passed.
- Alignment audit: 20 passed, 0 failed.
- The tokenizer correctly mapped both locations of real multi-location
  annotations to valid token indices.

**Decision:** Adopt tokenizer offset mappings for BIO-label construction.

**Why it worked:**

- Tokenizer offset mappings are generated by the tokenizer itself and
  account for subword tokenization.
- The former `str.find()` approach failed on repeated text and subword
  tokens, producing incorrect or missing labels.
- The audit compared the implementation against independently derived
  expected labels for every audited passage.

**Process lesson:**

- Do not use exact multi-line string replacement for edits in this
  repository.
- Windows line endings and invisible whitespace differences can make
  visually identical code fail an exact-string match.
- Use unique single-line anchors, verify their locations, apply bounded
  line-based edits, and run focused tests immediately.

**Provenance:**

- Implementation: `src/ner/transformer_ner.py`
- Tests: `tests/golden/test_transformer_bio_locations.py`
- Alignment audit: 20 multi-location development passages
- Local model: `models/pubmedbert-local/`

**Follow-up:** Run a tiny CPU overfit preflight before full training.

## EXP-002: Partial-overlap false-negative audit

**Date:** 2026-10-11  
**Status:** IN PROGRESS  
**Research question:** Are the 891 partial-overlap false negatives caused by
a small number of consistent boundary, punctuation, or normalization
patterns that can be addressed without sacrificing precision?

**Hypothesis:** A subset of partial overlaps may share a consistent
boundary or surface-form pattern, but the audit must determine this before
changing the matcher.

**Method:**

- Use the BC5CDR development set only.
- Use the baseline dictionary and Gate C-2 location-level, type-aware
  exact-span policy.
- Identify false-negative gold spans that overlap at least one predicted
  span.
- Categorize overlap direction and text-boundary relationships.
- Produce counts, representative examples, and candidate intervention
  categories.
